# SIH PS 26092 — SC Concessional Credit Access Platform

**This page describes one focused module inside the larger YojnaSetu /
Yojna Sarthi codebase — the part built specifically for SIH 2026 Problem
Statement 26092 (Ministry of Social Justice & Empowerment / NSFDC).** It
is intentionally self-contained: everything below can be read, demoed and
evaluated without knowing anything about the rest of the platform. See the
[main README](../README.md) for the full 13-agent product this module lives
inside of.

## The problem statement

NSFDC channels concessional credit to Scheduled Caste citizens through
Channel Partner banks, at rates that vary sharply by which institution
processes the loan (the same Micro Finance scheme is 6.5% through a State
Channelising Agency and up to 15% through an NBFC-MFI). The people this
money is for — small entrepreneurs, first-generation applicants — routinely
don't know the scheme exists, don't know which of several near-identical
schemes applies to them, and have no way to compare branches before
committing to one.

## Why this isn't just "another scheme directory"

nsfdc.nic.in and myscheme.gov.in already publish this information, and as
the government's own primary source they will always be more authoritative
than a hackathon build. A static catalogue page — "here are 6 schemes, read
their eligibility criteria" — cannot out-compete that. The one thing an AI
layer can add is translation: a citizen doesn't arrive knowing the phrase
"unit-cost ceiling", they arrive knowing "I want to open a tea shop and I
don't have much money." This module's entry point is a conversation that
turns that sentence into the real eligibility check, not a form that assumes
the citizen already knows what to fill in.

## What's live at `/startgo`

| Screen | What it does |
|---|---|
| **Ask Sathi** (`/eligibility`, and the default landing at `/startgo`) | Conversational intake — text or voice, in the citizen's own language. Sathi asks for what it still needs (need, project cost, income, category, gender), never more than that, then calls the real eligibility engine and shows the actual verdict next to the chat. |
| **Credit schemes** (`/credit-schemes`) | The 6 real NSFDC products, sourced from `credit_products` — the authoritative figures, not a hardcoded copy that can drift. |
| **EMI calculator** (`/emi-calculator`) | Reducing-balance EMI math including each scheme's real moratorium treatment (capitalise vs. service-interest — these produce materially different totals, and the UI states which is shown). |
| **Get help** (`/csc-finder`) | Real bank-branch lookup (OpenStreetMap, server-proxied), flagging which nearby branches can actually deliver a given scheme — a Public Sector Bank cannot process an NBFC-MFI-only product, and a citizen should know that before travelling there. |
| **Apply** (`/apply/:schemeId`) | The real 4-step application: draft → choose a real branch → consent (exact DPDP-2023 wording, fetched from the backend, never paraphrased) → submit. Backed by a validated state machine (`CreditApplicationStatus`), not a form that posts into a void. |

## The one hard rule

**Nothing in this module ever answers "you qualify" from an LLM's own
reasoning.** The conversational assistant only extracts structured facts
from what the citizen says (deterministic regex first, LLM only for what
regex misses, LLM never overrides a deterministic hit) and then calls the
same real `POST /api/v2/sih/credit/eligibility` a plain form would call. If
that call fails, the honest answer is "couldn't check right now" — never a
guessed figure. This is a direct lesson from a real bug caught during
development: an earlier version of this UI quoted a scheme's *unit-cost
ceiling* as the *loan amount*, overstating one product by ₹15,000 and
another by ₹5 lakh. The fix wasn't "be more careful" — it was "the UI is
never the source of truth for a number a citizen might rely on; the backend
is, always."

## Architecture

```
Browser (React, /startgo)
   │  text or recorded audio
   ▼
FastAPI ai_service
   /eligibility-assistant/chat   — text turn
   /eligibility-assistant/voice  — Sarvam STT → same assistant → Sarvam TTS
   │  extracted facts only, never a verdict
   ▼
Spring Boot gateway
   /api/v2/sih/credit/eligibility  — CreditEligibilityService (authoritative)
   /api/v2/sih/credit/products     — credit_products (6 real NSFDC schemes)
   /api/v2/sih/applications/*      — CreditApplicationStatus state machine
   /api/v2/credit-partners/nearby  — real branch lookup (OpenStreetMap)
   │
   ▼
MongoDB — credit_products, credit_applications, consents, digilocker_links
```

Both the eligibility chat and its voice counterpart are **stateless and
public** — no login, no server-side session. The browser holds the
conversation's `context` between turns and sends it back each request,
matching the "learn before you sign up" principle the eligibility endpoint
itself was already built around: a citizen must be able to find out what
they qualify for before creating an account.

## Honest gaps — what a judge should know before asking

- **DigiLocker and Account Aggregator are real, spec-shaped integrations
  with no live partner credentials.** Both are built end-to-end against
  their published APIs and gated by `isConfigured()`, which stays false
  until real credentials exist — see `DigiLockerService`'s own class
  javadoc. A **demo simulation mode** (`app.demo.simulate-integrations`,
  default off, never set in the deploy script) walks the identical UI flow
  with canned data, and every simulated response is labelled `simulated:
  true` end to end so it can never be mistaken for a real verification.
- **Sarvam's own TTS endpoint currently 400s** on this deployment (a
  configuration issue on the Sarvam side, not something this module
  controls); its documented gTTS fallback covers the gap, so voice replies
  still work, just via the fallback voice rather than Sarvam's.
- **Aadhaar offline eKYC** genuinely parses a real UIDAI ZIP and verifies
  its structure, but signature verification stays `false` without a
  production UIDAI certificate — reported to the citizen as "not
  cryptographically verified in this deployment," never hidden.
- **Discovery (finding new/updated schemes from myscheme.gov.in)** is real
  and has been run live against the production myScheme API — see the main
  README's Agent 2 row — but a full catalogue sync is a multi-hour job by
  myScheme's own rate limit (1 request/2s), not something triggered
  casually during a demo.

## Running just this module

The credit/eligibility module needs the same three services as the rest of
the platform — MongoDB, the Spring Boot gateway, and `ai_service` — see the
main README's setup section. Once running, `/startgo` is a complete,
self-contained demo path that never requires signing in.
